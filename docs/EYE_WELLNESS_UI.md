# 안구 건강 대시보드

`src/v2/deploy/pi_demo.py`의 OpenCV/Pillow 네이티브 화면. 브라우저나 웹 서버 없이 기존 Raspberry Pi 추론 경로로 실행한다. 흰색 카드와 파란색 강조, 기본 1280×720이며 다른 `--canvas` 크기는 비율을 유지해 확대·축소한다. 800×480에서는 위아래 여백이 생기며 발표 캡처는 1280×720 이상을 권장한다.

## 실행

기존 Pi 저장소의 같은 위치에 `pi_demo.py`를 복사한 뒤, Pi 데스크톱/VNC 터미널에서 실행한다.

```bash
cd ~/IEEE_sensors
conda activate eyeblink
python -m pip install 'pillow>=10.0.0'
sudo apt install -y fonts-nanum
python -m src.v2.deploy.pi_demo --source 0 --fullscreen
```

맥북 카메라 서버를 사용하는 기존 구성은 `--source http://<맥북IP>:8000/stream.mjpg`로 실행한다. 모델 경로, 사용자 프로필 파일, 임계값 조정 및 등록 단축키는 기존과 같다. `--mode ear`는 규칙 기반 검출 모드이며 임베딩 기반 식별은 제공하지 않는다.

| 키 | 기능 |
|---|---|
| 1~6 | 사용자 등록·재등록 |
| r / c | 식별 버퍼 / 세션 카운터 초기화 |
| [ / ] | 식별 임계값 조정 |
| - / = | 깜빡임 임계값 조정 |
| s | 현재 화면 PNG 저장 |
| f / q / Esc | 전체화면 전환 / 종료 / 종료 |
| x | 기존 기능: 등록 프로필 전체 삭제 |

## 발표용 이미지

```bash
python -m src.v2.deploy.pi_demo --preview output/eye_wellness_ui/dashboard_preview.png
python -m src.v2.deploy.pi_demo --preview output/eye_wellness_ui/dashboard_preview_1920.png --canvas 1920x1080
```

미리보기는 카메라·모델 없이 동일한 화면 렌더러를 실행한다. 인물 도형과 수치는 예시이며 실제 측정 결과가 아니다. 프로필을 읽거나 저장하지 않는다. 실제 발표의 **실증 결과** 영역에는 Pi에서 실시간 실행한 후 `s`로 저장한 `results/v2/demo_shots/demo_*.png`를 삽입한다. 별도로 제공한 미리보기 PNG는 레이아웃 검토용이다.

## 화면과 참고 문서의 대응

- 카메라: 머리카락 없는 사람 실루엣 위 사각형에 정규화된 눈 크롭(160×64)만 실시간 표시. 나머지 얼굴·배경 영상은 화면에 전달하지 않는다. 검출 실패·연결 단절 시 눈 크롭을 비운다.
- 깜빡임: 세션 횟수, 최근 60초 빈도, 마지막 깜빡임 이후 경과, 확률·임계선과 최근 150프레임 그래프 유지.
- 사용자 식별: 유사도·임계값, 최대 6명 등록 사용자 표시. 미등록 또는 입력 없음 상태를 구분.
- 개인별 이력: 누적 깜빡임·관측 시간, 기준선 대비 현재 빈도와 관리 안내 유지. 관측 부족 시 공통 초기값임을 표시.
- 하단: `처리 14.7 fps` 형식의 FPS만 표시. 파이프라인·단계별 지연·장치 정보는 화면에서 제외한다. 미리보기의 14.7은 예시이고 실제 실행은 기존 FPS 측정값을 사용한다.

발명신고서의 사용자별 분리·누적, 동일 임베딩 공유, 기준선 기반 안내를 화면에 반영했다. 기존 데모의 기준선 계산(누적 평균, 기본 최소 60초)은 유지했다. 문서에 있는 7일 중앙값/IQR, 2시간 초기 관측, 화면 밝기·색온도 자동 조정은 이번 화면 변경에서 추가 구현하지 않았다. 사용자 식별 정확도나 논문 지연 수치를 화면에 고정값으로 넣지 않는다.

일반 실행은 영상 파일을 자동 보관하지 않지만 `s`, `--shot-every`로 저장한 화면에는 눈 크롭 영상만 포함된다. 원격 MJPEG 입력은 네트워크로 Pi에 들어온다. 이에 맞춰 기존 화면의 포괄적인 ‘외부 전송 없음’ 문구를 실제 동작을 설명하는 문구로 바꿨다.

검증: 로컬에서 동일 렌더러의 정상·미등록·공통 기준선·미검출·입력 대기·6인 목록 및 여러 해상도를 확인했다. 실제 Pi 하드웨어의 카메라·ONNX 추론·FPS는 별도 현장 확인이 필요하다.
