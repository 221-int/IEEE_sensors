[핵심 과제 1] 표현(벡터) 재설계 — 이번 라운드의 진짜 주제
──────────────────────────────────────────────────────────────

기존 설계는 "눈 크롭 → 오토인코더(복원 MSE) → 128차원 → MLP"였고, 결과는 이렇다.

- 선형 프로브 재식별 0.994 (8명, chance 0.125) — 벡터가 신원을 거의 전부 담고 있다
  (results/identity_probe.json)
- 잠재 차원을 512 → 32 로 16배 좁혀도 재식별이 0.9992 → 0.9947, 즉 0.45%p만 줄었다
  (results/dim_sweep.json)

여기서 나오는 진단을 먼저 확인하고 시작해라:
**차원은 원인이 아니다. 차원 축소 재시도는 이미 기각된 길이니 반복하지 마라.**
그렇다면 남는 후보 원인은 목적함수·입력 표현·병목의 형태다.
복원 MSE는 "외형을 보존하라"는 목적이고, 눈 크롭에서 외형은 곧 신원이다.

너의 일은 이 진단이 맞는지 스스로 판단하고, mEBAL2에 맞는 표현을 새로 설계하는 것이다.
아래 네 축을 각각 검토해라. **"현재 방식 유지"를 고르더라도 근거를 대라.**

축 1 — 입력 표현
  후보: 단일 프레임 64×160 / 19프레임 시퀀스 통째 / 프레임 차분·시간 미분 /
        눈꺼풀 운동 요약 / 그 조합
  생각할 것: mEBAL2의 라벨 단위가 애초에 19프레임 이벤트다. 단일 프레임 표현은
  이 구조를 버린다. 반대로 외형은 정적이고 깜빡임은 동적이라는 성질은
  입력 단계에서 신원을 줄이는 데 쓸 수 있는가? 쓸 수 있다면 대가는 무엇인가?

축 2 — 학습 목적함수
  후보: 복원 MSE(현재) / 깜빡임 지도학습 직접 / 대조학습 / 시간적 예측 / 조합
  생각할 것: 복원 목적이 재식별 99%의 원인이라는 가설은 아직 검증되지 않았다.
  이 가설을 가장 싸게 반증·입증할 실험은 무엇인가? 그 실험을 설계 결정보다 먼저 해라.

축 3 — 병목의 형태
  후보: 연속 실수 D차원(현재) / 변분 정보 병목(VIB) / 이산 코드(VQ) / 희소성 / 양자화 비트수
  생각할 것: 58명 식별에 필요한 정보량은 5.9비트다. 연속 실수 128차원은 그에 비해
  과잉이다. "차원"이 아니라 "표현 가능한 정보량"을 제한하는 것은 다른 축인가,
  아니면 결국 같은 것이라 똑같이 실패하는가? 이 구분을 명확히 답하라.

축 4 — 신원 억제 기전
  후보: GRL/DANN(기존 예비 결과 있음, 한쪽눈 64×64라 인용 금지) /
        상호정보 최소화 / 적대적 프로브 / 사후 투영 제거 / 없음
  생각할 것: 억제를 학습에 넣는 것과 학습 후에 제거하는 것의 차이는 무엇인가?
  배포 경로(Pi5)에서 실행 비용이 드는 쪽은 어디인가?

**필수 요구사항**
- 네 축은 서로 교락된다. 한 번에 여러 축을 바꾸면 무엇이 효과를 냈는지 알 수 없다.
  한 번에 하나씩 바꾸는 ablation 순서를 명시해라
- 차원 D를 정할 때 "128"을 기본값으로 쓰지 마라. mEBAL2 기준으로 근거를 대라
- 각 설계안마다 **실패 시나리오**를 먼저 적어라. "이 안이 틀렸다면 어떤 숫자로 드러나는가"
- Pi5 예산(프레임당 33.3 ms, 30 fps) 안에 들어가는지 각 안마다 추정치를 붙여라.
  기존 인코더는 인코더+MLP 2.25 ms, e2e 11.53 ms였다. 시퀀스 입력은 이 비용을 바꾼다

**대조군 (빠뜨리면 결과가 무의미하다)**
- EAR 스칼라 + 동일 MLP + 동일 19프레임 시간창  ← 이걸 못 이기면
  기여는 "표현"이 아니라 "학습된 판정 규칙"이다. 가장 아프고 가장 필요한 대조군이다
- 크롭 → 소형 CNN 직접 (표현 단계 없음)
- 동일 차원 random projection
- 평균 벡터 (정보 0의 하한)

[핵심 과제 2] 평가 설계 — 코드를 쓰기 전에 확정해야 한다
──────────────────────────────────────────────────────────────

**막혀 있는 결정 하나가 있다. 이것부터 답해라.**

재식별 프로브를 폐쇄집합(closed-set) 58-way 분류로 갈 것인가,
아니면 검증(verification, 미지 신원 쌍이 같은 사람인가)으로 갈 것인가?

- 폐쇄집합 58-way 분류기를 학습하려면 58명 전원의 프레임이 train에 있어야 한다.
  즉 재식별 축은 **피험자 공유 + 프레임/시간 분리**여야 성립한다
- 반면 깜빡임 분류(유용성 축)는 **피험자 분리**여야 한다
- 이 둘을 섞으면 코드를 다시 짜게 된다. npz 스키마까지 영향을 받는다

그리고 mEBAL2는 **한 사람당 세션이 하나뿐**이라는 구조적 한계가 있다. train/test가
같은 20분 녹화 안에서 갈리므로, 프로브가 "누구인가"가 아니라 "어느 세션인가"
(조명·카메라 각도·안경 반사·배경)를 맞출 수 있다. 58-way 0.99가 나와도 신원 누출의
증거로 단정할 수 없다.
→ 최소한 **세션 앞 70% / 뒤 30% 시간 블록 분할**을 무작위 분할과 나란히 보고해라.
   두 숫자의 격차 자체가 "신원인가 세션인가"에 대한 답이다.

**보고할 지표**
- privacy 축: 58-way 재식별 정확도 (chance 0.017), 선형 프로브와 MLP 둘 다,
              무작위 분할 / 시간 블록 분할 병기
- utility 축: 균형 1:1 blink/unblink 이벤트 분류 (19프레임 시퀀스 단위),
              피험자 분리 5-fold, accuracy · PR-AUC · precision · fold 부트스트랩 CI
- 파레토 곡선: x=privacy, y=utility. **utility를 유지하면서 identity만 내려가는 구간이
  존재하는가**가 이 프로젝트에 남은 유일한 정당화 근거다
- 연속 event recall / frame false-alarm 은 **측정하지 마라** (라벨 커버리지 12%)

- 동일한 분위수 격자를 ours와 baseline에 똑같이 적용해라. 다른 격자를 쓰면 결과가
  뒤집힌다. 이 버그가 세 번 났고 원인 코드가 아직 남아 있다
- 단일 시드 결과로 baseline과 비교하지 마라. 시드 하나가 결론을 뒤집는다
- val에서 고르고 val에서 보고하지 마라. 낙관 편향 +0.085가 실측됐다
- cudnn.deterministic 을 설정하기 전까지 어떤 ± 숫자도 인용하지 마라
- 새 실험은 대조군을 먼저 정해라. PSNR 하나만 보면 정보 0인 평균 이미지도 높게 나온다
- 임계값 보정은 인과적(과거만 사용)이어야 한다. rank·zscore는 비인과적이라 배포 불가다.
  성능이 좋아 보여도 해법으로 쓰지 마라
- **결과가 유리하게 나오면 베이스라인이 불리해진 것은 아닌지 먼저 의심해라.**
  mEBAL2 안경 착용자는 깜빡임 시 EAR이 0.34→0.21로 38%만 하강한다(완전 폐안이면 더
  떨어져야 함). EAR은 랜드마크 의존이라 크게 망가지고 우리는 크롭을 직접 보므로 덜
  망가진다. "우리가 EAR을 이겼다"가 나와도 방법이 좋아서가 아니라 베이스라인이
  불리해서일 수 있다. 안경 착용/미착용 분리 보고 항목을 설계에 넣어라
- **사용자 간 밝기 분산이 미측정이다.** Eyeblink8 102.7 vs mEBAL2 34.8~45.4 는 확인됐지만
  mEBAL2 58명 사이의 분산은 잰 적이 없다. 사용자마다 밝기가 다르면 재식별 프로브가
  신원이 아니라 밝기를 외울 수 있다. 전처리를 확정하기 전에 이것부터 재라
- 신원 수가 8 → 58로 늘면 EAR은 chance 쪽으로 내려가는데 우리 벡터는 0.99대를 유지할

## 이 프롬프트를 쓰면서 바뀐 것

| 항목 | 이전 | 이번 라운드 |
|---|---|---|
| 데이터셋 | Eyeblink8(주) + mEBAL2(신원) | **mEBAL2 단독** |
| 최종 목표 | 깜빡임 → 눈 건강 위험 지표 | **신원이 분리된 깜빡임 표현 학습** (눈 건강 지표 제외) |
| 유용성 지표 | 연속 event recall + frame FA | **균형 1:1 인스턴스 분류** (19프레임 시퀀스) |
| 표현 | 복원 오토인코더 → 128차원 고정 | **네 축 전면 재검토** (입력·목적함수·병목·억제) |

| Pi5 실측 | 확정된 결과로 인용 | **인코더가 바뀌면 무효 → 재측정 대상** |

## 남는 리스크 (프롬프트에 넣었지만 다시 짚음)

- **눈 건강 지표를 목표에서 빼면 "왜 깜빡임인가"의 응용 근거가 얇아진다.** 지금 남는 논리는 "깜빡임은 신원과 분리 가능한 표현을 검증하기에 좋은 과제"이지 "눈 건강을 모니터링한다"가 아니다. 교수님 제안 제목(*...for Eye Health Monitoring*)과 어긋나므로, 지도 미팅에서 이 축소를 한 번 확인받는 편이 안전합니다.
- **mEBAL2 세션이 1인 1개**라는 한계는 데이터로 해결되지 않습니다. 재식별 숫자가 "신원"인지 "세션"인지 끝까지 분리되지 않을 수 있고, 이건 리뷰어가 바로 짚는 지점입니다. 시간 블록 분할 병기가 최소한의 방어입니다.
