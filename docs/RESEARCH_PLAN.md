## 1. 연구 대상 정의

**과제** — eye blink detection. 라벨 단위는 mEBAL2 의 **19프레임 고정창 이벤트**이며,
blink / unblink 이진 분류다. 연속 영상 event recall 과 frame false-alarm 은
mEBAL2 라벨 커버리지 문제로 **측정하지 않는다** (`docs/v2/PROTOCOL.md` §12).

**입력 경로**

```
프레임 → 눈 위치 검출·추적 → 양눈 크롭 (그레이 64×160)
      → encoder (vpres) → embedding vector (D차원)
      → 19프레임 링버퍼 → 시간 헤드 → 판정 헤드 → blink / unblink
```

**핵심 제약** — 판정 헤드는 **embedding vector 만** 본다. 원본 크롭 픽셀은 encoder 이후로
넘어가지 않는다.

## 2. 연구 질문

### RQ1. embedding vector 만으로 눈 깜빡임을 정확히 검출할 수 있는가?

- **판정 기준** — 피험자 분리 5-fold × 3 seed 에서 PR-AUC 를 주 지표로 보고,
  EAR 베이스라인 대비 비열등(δ=0.02) 하한을 만족한다.
- **현재 근거** — `results/v2/train_encoder.json`: ours 0.9886 ± 0.0038 vs
  ear_head 0.9724 ± 0.0096, 차이 +0.0151 [+0.0106, +0.0203]. **비열등 충족, 형식상 superior.**
- **완료** — 확정 런의 사이드카를 사용해 이벤트 가중 풀링과 ear_head 상대 δ 판정을
  재실행했다. 결과는 `results/v2/posthoc_subgroups_final.json`에 있다.

### RQ2. embedding vector 기반이 EAR 기반보다 다양한 환경에서 더 안정적인가?

- **판정 기준** — `EXPERIMENT_PLAN.md` §4 의 조건별로 두 방법의 성능 저하폭을 비교한다.
  전체 · 조건별 숫자를 **항상 함께** 낸다.
- **현재 근거** — 이벤트 가중 풀링 기준으로 전체·2020·2022·안경·미착용 다섯 그룹이
  모두 `superior` 판정을 받았다. 안경군은 +0.0118, 95% CI [+0.0061, +0.0165]다.
- 피험자 평균과 이벤트 가중 풀링은 서로 다른 추정량이므로 둘 다 보존하고, 안경군 결과는
  추정량 민감성을 한계로 기록한다.
- **남은 것** — 조도 · 얼굴 각도 · 거리 · 부분 깜빡임 축은 mEBAL2 에 라벨이 없다.
  → **추가 데이터 수집 필요** 또는 **제어된 합성 열화(synthetic degradation)** 로 대체.

### RQ3. 원본 이미지 기반 모델 대비 정확도 · 속도 · 지연에서 경쟁력이 있는가?

- **판정 기준** — 동일 데이터 분할 · 동일 판정 헤드 · 동일 지표로 3자 비교
  (EAR / 이미지 CNN / embedding vector).
- **현재 근거** — 탐색 비교와 5-fold×3-seed 확정 런이 모두 있다. `image_cnn_max`와
  `image_cnn_head`를 분리해 시간 처리의 기여도 확인했다.
- 다만 문헌의 `max pooling` 비교는 원문 라벨 조건과 현재 창당 라벨 조건이 다르므로,
  문헌 방법 대비 차이는 그 한계를 함께 기록한다.

### RQ4. Raspberry Pi 5 에서 실시간으로 실행할 수 있는가?

- **판정 기준** — e2e p99 ≤ 33.3 ms (30 fps 예산), 5분 지속 측정, 스로틀 없음.
- **현재 근거** — v2 네 모드의 480p/720p 실측이 완료됐다. G-E1 판정과 단계별 지연,
  FPS·RSS·CPU·온도·스로틀 결과는 논문 문서 Table II-b에 기록되어 있다.
- **현재 상태** — v2 encoder·image_cnn ONNX export, 측정 하네스, 실제 Pi 5의 네 모드
  480p/720p 지속 측정과 G-E1 판정이 완료됐다. 세부 수치는 논문 문서 Table II-b를 참조한다.

### RQ5. 판정 단계에서 원본 이미지를 쓰지 않는 구조의 장점은 무엇인가?

- **이것은 실험이 아니라 설계 서술이다.** 논문 본문에서 한두 문장.
- 허용/금지 문장은 `PROJECT_DIRECTION.md` §5 를 그대로 따른다.
- **금지의 실측 근거** — 우리 embedding vector 의 57-way 재식별 0.6345 ± 0.0288
  (`results/v2/phase5_reid.json`)은 랜덤 인코더 0.6261 과 동급이다. 신원은 그대로 샌다.

### 4-2. 연구 가설 (미검증)

> **아래는 아직 증명되지 않았다. 논문에서 단정형으로 쓰지 않는다.**

| # | 가설 | 왜 그럴 법한가 |
|---|---|---|
| H1a | embedding vector 는 **눈의 모양**을 담는다 | encoder 가 크롭 픽셀 전체를 본다 |
| H1b | embedding vector 는 **눈꺼풀의 상태**(완전/부분 폐쇄)를 담는다 | 세로 해상도를 4.35 px 남기도록 설계했다 (F8) |
| H1c | embedding vector 는 **주변 밝기**를 담는다 | F7 이 크롭에 광학 정보가 있음을 보인다. 단 encoder 가 그것을 **쓰는지**는 별개 |
| H1d | embedding vector 는 **눈 주변의 질감**을 담는다 | 미검증. 근거 없음 |
| H1e | embedding vector 는 **부분적인 자세 변화**를 담는다 | 미검증. 크롭이 회전 정렬되므로 오히려 제거될 수도 있다 |
| H1f | embedding vector 는 **눈이 감기는 과정의 시각적 특징**을 담는다 | 19프레임 시간 헤드가 있으므로 구조적으로 가능 |
| H1g | embedding vector 는 **EAR 값만으로 표현하기 어려운 추가 영상 특징**을 담는다 | H1a~H1f 의 상위 명제 |
| H2 | 그 결과 저조도 · 얼굴 각도 변화 · 부분 깜빡임에서 EAR 보다 **성능 저하가 작다** | H1 이 참이면 따라온다. **단 F5 는 반대 방향의 증거다** |
| H3 | encoder 한 단이 추가돼도 edge device 실시간 예산 안에 들어간다 | v1 예비 근거만 있음 |

> 🔴 **F5 를 숨기지 않는다.** 안경군에서 이득이 사라진다는 것은 H2 에 불리한 실측이다.
> `docs/v2/PROTOCOL.md` §9 는 "안경에서 EAR 이 더 망가져 편향이 우리에게 유리하다"고
> **예상했으나 실측에서 뒤집혔다**고 기록한다. 예상이 아니라 실측을 쓴다.

### 4-3. 실험을 통해 검증해야 할 내용

| # | 검증 항목 | 방법 | 상태 |
|---|---|---|---|
| V1 | H1c — encoder 가 밝기 정보를 실제로 쓰는가 | 밝기를 인위적으로 변조한 크롭에서 성능 저하 비교 (EAR vs ours) | 미착수 |
| V2 | H1b · H1f — 부분 깜빡임 구분 | 부분 폐쇄 라벨이 있는 데이터 필요 → **추가 데이터 수집 필요** | 미착수 |
| V3 | H1g — 표현의 기여인가 학습 헤드의 기여인가 | image_cnn 두 변형으로 표현·시간 처리 분리 | ✅ image_cnn 확정 런 완료 |
| V4 | H2 — 조건별 저하폭 | `EXPERIMENT_PLAN.md` §4 조건별 표 | 부분 (안경·배치만) |
| V5 | H3 — edge 비용 | Pi 5 재측정 | ✅ ONNX·하네스·실제 보드 측정 완료 |
| V6 | embedding vector 가 실제로 무엇을 담는지 직접 확인 | 임베딩에 대한 속성 프로브(밝기·선명도·안경 여부 등) 회귀/분류 | 미착수. 저비용이라 우선 검토 |

   보고하고 Raspberry Pi 5 실측으로 실시간 동작을 확인한다. — ✅ **완료**
