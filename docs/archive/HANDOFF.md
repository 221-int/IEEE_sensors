## 2. 지금까지의 결과 (원자료는 `results/`)

### ✅ 확정 — 엣지 (`PI5_BENCHMARK.md`)

Pi 5 / Debian 13 / governor=performance / 액티브 쿨러 / 각 300초:

| | EAR | Ours |
|---|---:|---:|
| e2e p50 / p95 / p99 (ms) | 8.86 / 9.09 / 9.36 | **11.53 / 11.78 / 12.06** |
| 지속 fps | 112.3 | 86.1 |
| p99 / 30fps 예산(33.3ms) | 28% | **36%** |

벡터 표현 비용 **+2.67 ms (1.30×)**, 그중 84%가 인코더+MLP. 5분 스로틀 없음.

**측정 시 반드시 통제**: `--intra-threads 2 --no-spin` (ONNX spin-wait이 인접 단계를 27% 오염), governor=performance.

### ⚠️ 정확도 — 판정 불가 (`results/split_eval.json`)

피험자 4-fold 교차검증, **408 이벤트 전부 test 사용**, 임계값은 val에서 골라 얼려서 test 적용:

| | test recall | test FA |
|---|---|---|
| Ours | **0.854 ± 0.226** | 0.0495 ± 0.1028 |
| EAR (양눈 mean) | **0.878 ± 0.206** | 0.0342 ± 0.0264 |

차이 −0.024, 흔들림 폭 안 → **우열 판정 불가.** val 선택 낙관 = **+0.085** (0.938→0.854).

### ★ 새 발견 — 임계값 보정 (`results/split_eval_calib.json`)

절대 확률 임계값이 피험자를 넘어가지 못한다. **분위 순위(rank) 보정이 이를 해결한다:**

| 보정 | Ours recall | Ours FA | 최악 FA |
|---|---|---|---|
| none (현재) | 0.803 ± **0.321** | 0.0366 ± **0.0650** | 0.245 |
| **rank** | **0.955 ± 0.042** | **0.0257 ± 0.0041** | **0.034** |
| zscore | 0.595 ± 0.456 | 0.0336 ± 0.0281 | 0.084 |
| rolling | 0.593 ± 0.378 | 0.0431 ± 0.0318 | 0.100 |

**rank: recall +0.152, recall 표준편차 0.321→0.042, FA 표준편차 15.7배 감소.**
같은 조건 EAR은 0.975±0.029 → **rank 보정 시 우리(0.955)가 EAR에 근접**한다.

⚠️ 예상과 달리 `rolling`/`zscore` 는 오히려 나빠졌다. 원인 미규명 — 윈도우 길이(150프레임)
또는 에폭 선택을 보정 없는 확률로 한 탓일 수 있다. **확인 필요.**

### ❌ 기각된 가설 (`results/dim_sweep.json`)

- **"128이 병목"** → 기각. 32차원으로도 충분
- **"차원을 좁히면 프라이버시"** → 기각. 512→32(16배)에도 선형 재식별 **99%+**

### 🔓 프라이버시 (`results/recon_attack.json`, `docs/figures/recon_attack_*.png`)

공격자가 디코더를 새로 학습해 미지 신원 복원:

| ours | attacker | mean(정보0) | shuffled |
|---|---|---|---|
| 33.79 dB | **23.13 dB** | 17.26 dB | 20.02 dB |

총이득 +5.87dB = 일반적 눈 형태 +2.76 + **벡터 고유 +3.11**. 디코더 미배포 장벽 = **10.65 dB**.
그림상 육안 식별은 **불가**. → "복원 불가"가 아니라 **"복원 곤란"** 으로 표현을 낮출 것.

**더 중요**: 재식별은 이미지를 복원하지 않고도 **선형 프로브 99.8%**.
→ **프라이버시 병목은 복원이 아니라 신원이다.**

### 🔬 눈 건강 지표 — 계산됨 (아직 문서화 안 함)

`.tag` 의 `LE_FC`/`RE_FC`(좌·우 완전폐안) 라벨을 쓰면 지금 바로 나온다:

| | 전체 | 범위 |
|---|---|---|
| 깜빡임 빈도 | 10.3 /min | 4.4 ~ 15.8 |
| 불완전 깜빡임 | 4.9% | 0 ~ 18.5% (eb03) |
| PERCLOS | 2.53% | 0.88 ~ 5.72% |

단안 깜빡임은 폐안 프레임의 **3.2%(58프레임)뿐** → 좌우 비대칭 주장은 이 데이터로 검증 불가,
