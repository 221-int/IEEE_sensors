## 1. 정정 — "EAR과 대등, 우열 판정 불가"는 성립하지 않는다

**정정 전 (폐기)** — `results/split_eval.json`

| | test event recall |
|---|---|
| Ours | 0.854 ± 0.226 |
| EAR (양눈 평균) | 0.878 ± 0.206 |
| 차이 | −0.024 → "흔들림 폭 안, 판정 불가" |

**정정 후 (유효)** — `results/split_eval_calib.json`, 보정 `none` 조건

| | test event recall |
|---|---|
| Ours | **0.803 ± 0.321** |
| EAR (양눈 평균) | **0.977 ± 0.035** |
| 차이 | **−0.174 → 제안 방식이 EAR에 진다** |

### 원인

두 실행의 EAR 임계값 선택 격자가 다르다.

| | `split_eval.json` (폐기) | `split_eval_calib.json` (유효) |
|---|---|---|
| EAR 임계값 fold0 / fold1 | **0.215 / 0.100** | −0.2104 / −0.1901 |
| 격자 | 성긴 고정 격자 (0.005 단위 반올림값) | `threshold_grid()` 분위수 97점 |
| 부호 규약 | 원 EAR (낮을수록 발화) | 부호 통일 후 ours·EAR 동일 처리 |

`0.100`은 격자 경계값이다. 성긴 격자가 저FA 구간을 짚지 못해 fold1에서 EAR recall이
**0.521**로 깎였고, 그 한 칸이 "대등"이라는 결론을 만들었다.

**이것은 `PROJECT_DETAILED.md` §8.2 와 `HANDOFF.md` §6 이 이미 두 번 경고한 바로 그 버그이며,
세 번째다. 이번에는 우리 쪽에 유리하게 작동했다.**

### 재발 방지

- 모든 비교는 분위수 격자(`threshold_grid`)로 고정한다.
- ours 와 EAR 은 **동일한 격자 생성 함수 · 동일한 부호 규약**을 통과시킨다.
- 격자를 바꾼 실험은 반드시 양쪽을 함께 다시 돌린다.

## 2. 정정 — `rank` 보정은 "문제 해결"이 아니다

`rank` 는 피험자의 **전체 녹화분을 미리 보고** 분위 순위를 매기는 **비인과적(transductive)**
방식이다(`src/experiments/split_eval.py:125` 주석에 명시). Pi 5에서 프레임 단위로 도는
시스템은 미래 프레임을 볼 수 없으므로 **배포 불가**다.

배포 가능한 보정은 오히려 악화했다.

| 보정 | 배포 가능 | Ours recall |
|---|---|---|
| none | ✔ | 0.803 ± 0.321 |
| rank | ✘ 비인과적 | 0.955 ± 0.042 |
| zscore | ✔ | 0.595 ± 0.456 |
| rolling | ✔ | 0.593 ± 0.378 |

**유효한 결론**: rank 가 성능을 되돌린다는 사실은 *손실의 대부분이 표현이 아니라
신원별 미교정에서 온다*는 **원인 진단**으로만 쓸 수 있다. 해법은 아직 없으며,
온라인 캘리브레이션(초기 등록 구간)이 별도 설계 과제로 남는다.

`HANDOFF.md` §2 의 "★ 새 발견 — 임계값 보정 / rank 가 이를 해결한다" 및
§3(4) 의 "슬라이드 B를 '문제 해결'로 완성할 것" 은 **철회한다.**

## 3. 정정 — 프라이버시 서술

`results/identity_probe.json` (2026-07-30):

| 표현 | 차원 | 선형 프로브 재식별 |
|---|---|---|
| ours 벡터 | 128 | **0.994** |
| EAR 스칼라 | 1 | 0.170 |
| EAR 창 128프레임 | 128 | 0.224 |
| EAR 창 요약통계 | 10 | 0.324 |

chance = 0.125. **제안 표현은 EAR 대비 신원을 훨씬 많이 흘린다.**

따라서 다음 서술은 **모두 틀렸다**:

- `README.md` "프라이버시 우선"
- `OVERVIEW.md:15`, `PROJECT_DETAILED.md:12,39` "디코더 미배포 → 복원 수단 자체가 부재 / 복원 불가"
- `STATUS_AND_DIRECTION_1.md:72` "구조에서 나온다 → 원본 복원 불가"

정정:

1. 복원은 **"불가"가 아니라 "곤란"**이다. 공격자가 다른 피험자만으로 디코더를 새로 학습해
   미지 신원을 PSNR 23.13 dB로 복원한다(shuffled 대조군 20.02, mean 17.26, 벡터 고유 기여 +3.11 dB).
2. **더 중요한 것**: 재식별은 이미지를 복원할 필요조차 없다. 선형 프로브만으로 99.4%다.
3. 따라서 **"프라이버시 우위"는 현재 주장할 수 없다.** 남은 가설은 하나뿐이다 —
   *"능력을 유지한 채 신원 축만 제거할 수 있다(disentanglement)"*.
   이를 뒷받침하는 **양눈 기준 결과는 현재 0건**이다(기존 λ 스윕은 한쪽눈 64×64 예비 결과이며
   양눈 npz와 호환되지 않는다).

### mEBAL2(**58명**)로 해결되지 않는 것

- 재식별 서열은 뒤집히지 않는다. 표본 수의 문제가 아니라 정보량의 문제다.
- mEBAL2는 통제된 실험실 수집이라 악조건(저조도·안경 반사·측면 각도)을 주지 않는다.
- 크롭 좌표를 MediaPipe에서 얻는 한, 랜드마크가 깨지면 우리 경로도 같이 깨진다.
- 인과적 임계값 문제·재현성·평가 지표 부재는 데이터와 무관한 코드/프로토콜 문제다.
- 68점 랜드마크 어댑터는 인덱스 교체로 끝나지 않는다. `.tag` 눈꼬리 기반 크롭과
  같은 분포를 주는지 **검증 실험이 필요**하다. 아니면 Eyeblink8 결과와 비교 불가능해진다.
