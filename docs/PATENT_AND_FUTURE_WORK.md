## 0-ter. 🔵 특허에 **실제로 넣을 수 있는 것**과 없는 것

전사문의 원래 구상은 *"눈 깜빡임 검출 + 신원 내용"* 이었다(16:56).
그런데 **신원 쪽은 실시가능성(enablement) 문제가 있다.**

### 우리가 실제로 가진 것 — 실측으로 뒷받침됨

| # | 기술 요소 | 근거 |
|---|---|---|
| **1** | 판정 단계가 원본 픽셀이 아니라 **D차원 임베딩 벡터**만 입력받는 온디바이스 깜빡임 검출 파이프라인 | PR-AUC 0.9886 ± 0.0038, 파라미터 **84,049**, ONNX **335 KB** |
| **2** | 🔴 **프레임당 인코딩 1회 + N프레임 링버퍼 + 시간 헤드** — 창마다 재인코딩하지 않는다 | **236.4 → 12.44 MMAC/frame (19배)** 실측. 이것이 에지를 가능하게 하는 핵심 |
| 3 | 두 눈 중심 거리에 **비례한 크롭 + 회전 정렬** → 카메라 거리·기울기에 불변인 고정 크기 입력 | MARGIN 2.2, 64×160 |
| 4 | 얼굴 해소 실패 프레임을 **마스크로 표시해 시간 pooling 에서 제외** | "변화 없음"과 "모름"의 구분 |
| 5 | 프레임 자기 통계 기반 입력 표준화(인과적) | 광학 교란 0.329 → 0.080 |
| 6 | 배포 경로에 **디코더 부재** — 원본을 저장·전송하지 않는 구성 | 구조적 사실 |

### 우리가 아직 갖지 못한 것 — **청구항의 중심에 두면 위험하다**

| 항목 | 실측 상태 |
|---|---|
| encoder 단 **신원 제거** | 🔴 **안 됨.** 재식별 0.6345 = **랜덤 인코더(0.6261)와 동급.** 목적함수도 차원 축소도 누출을 못 줄였다 |
| **원본 복원 방지** | 미측정 (v2 에서 한 번도 안 쟀다) |
| 깜빡임 특징으로 **사용자 식별** | 미측정. 문헌은 깜빡임 동역학만으로 **93.94% 식별** 가능하다고 보고(§1-2) |

> 🔴 **만들지 않은 것을 주 청구항으로 쓰면 나중에 무효 사유가 된다.**
> 전사문 12:50 의 *"거기에다 억지로 그냥 신원을 쑤셔 넣으려 했던 것"* 이라는 자평이
> 특허에서도 그대로 유효하다.

### 🔵 권고 — 특허의 중심을 옮긴다

**중심 = "온디바이스 임베딩 기반 눈 건강 모니터링"** (위 1~6)
**신원 = 종속항 / 확장 실시예**

이 배치가 좋은 이유:

1. **지도교수 지시("눈 건강 관련 특허")에 정면으로 부합한다** (전사문 12:50)
2. **우리가 실제로 만든 것이다.** 실시가능성 문제가 없다
3. **논문과 내용이 겹치므로 "먼저 출원해야 할 진짜 이유"가 생긴다** — 논문이 공개되면
   요소 1~6 이 전부 선행 기술이 된다. 이것이 순서 제약의 실질적 근거다
4. 신원은 **방법 청구항**(예: 인코더 학습 시 신원 판별 헤드에 기울기 반전을 적용하는 단계)
   으로 기술하면 실험 없이도 설명 가능하다. 다만 **주 청구항으로는 쓰지 않는다**

### 실시예 — 전사문에서 이미 나왔다

**화상회의 중 눈 건강 모니터링** (전사문 14:51~15:40)

1. 화상회의 중 카메라 프레임에서 눈 영역 크롭
2. 로컬 encoder 로 임베딩 벡터 변환 — **원본 프레임은 기기 밖으로 나가지 않는다**
3. 깜빡임 빈도 산출, 임계 이하이면 사용자에게 알림
4. (확장) 다중 참가자 환경에서 사용자별 통계 분리 ← **여기에 신원이 들어간다**

> 횟수나 (…) 그런 거를 좀 특징 잡아가지고 사람을 구별할 수 있지 않을까 생각하긴 했었는데

### 1-3. 우리 실측 기준선

`results/v2/phase5_reid.json` (57명, 균형 표집)

## 3. 원본 복원 방지 · 디코더 공격 — 후속 연구 §1

> 이전에 `docs/v2/PROTOCOL.md` §14 였던 내용. **설계는 유효하며 측정만 안 됐다.**
> 구현 예정 파일: `src/v2/phase5b_recon.py` (**미작성**).

### 3-1. 위협 모델

**"디코더를 배포 안 하니까 안전하다"는 성립하지 않는다.**

공격자는 저장·전송되는 **벡터를 가지고 있다**(그것이 시스템이 내보내는 전부다).
우리 디코더는 없지만 **(이미지, 벡터) 쌍을 스스로 만들 수 있다** — 배포된 encoder 에
자기 이미지나 공개 눈 데이터셋을 넣으면 된다. 따라서 **디코더를 새로 학습할 수 있다.**
디코더 미배포는 장애물이지 불가능성이 아니다.

v1 에서 실제로 공격자 디코더가 미지 신원을 **PSNR 23.13 dB** 로 부분 복원했고,
그래서 "복원 불가" 주장이 **"복원 곤란"으로 하향**됐다 (2026-07-30).

### 3-2. 분할

| | 역할 |
|---|---|
| 공격자 학습 | fold rotation 의 **train 피험자**의 (z, x) 쌍으로 디코더를 처음부터 학습 |
| 공격 대상 | **test fold 피험자** — 공격자가 한 번도 본 적 없는 신원 |

같은 사람으로 학습하고 그 사람을 복원하면 그건 암기다.

### 3-3. 필수 대조군 4개 🔒

눈 크롭은 저분산 그레이스케일이라 **아무 정보 없이도 PSNR 이 높게 나온다.**
**PSNR 숫자 하나는 의미가 없다.** 네 값을 항상 함께 낸다.

| # | 조건 | 무엇을 방어하나 |
|---|---|---|
| 1 | **ours** — 우리 디코더 | 복원의 상한 |
| 2 | **attacker** — 공격자가 새로 학습한 디코더 | 실제 공격 성공도 |
| 3 | **mean** — 학습셋 평균 이미지 출력 | 정보 0 의 하한 |
| 4 | **shuffled** — 공격자 디코더에 짝이 안 맞는 벡터 입력 | 디코더가 벡터를 실제로 읽는가 |

**판정**: `attacker` 가 `max(mean, shuffled)` 와 피험자 부트스트랩 CI 가 겹치면 복원은
사실상 실패한 것이다. 뚜렷이 위면 벡터가 외형을 흘리고 있다.

### 3-4. 지표

| 지표 | 성격 |
|---|---|
| PSNR (dB), MAE | 화질. **단독 인용 금지** |
| **복원 이미지 → 재식별** | **주 지표.** "얼마나 비슷하게 생겼나"보다 "복원본으로 사람을 특정할 수 있나"가 프라이버시 질문이다 |

해석 기준선은 같은 표집으로 잰 **원본 픽셀 0.9080**.

### 3-5. 게이트 (이전 G-R)

| | 기준 |
|---|---|
| G-R1 보고 완료 | 4대조군 × (PSNR · MAE · 복원본 재식별) 전부 보고 |
| G-R2 장벽 성립 | `attacker` 복원본 재식별의 부트스트랩 CI 상한 < **0.454** (원본 픽셀 0.9080 의 절반) |

> ⚠️ 0.454 는 상대 기준이지 실측 근거가 있는 절대값이 아니다. **결과를 보기 전에**
> 적어 얼린 값이며, 결과를 본 뒤 고치지 않는다.

## 4. 신원 억제 + 파레토 — 후속 연구 §2

> 이전에 `docs/v2/PROTOCOL.md` §15 였던 내용.
> 구현 예정 파일: `src/v2/phase7_pareto.py` (**미작성**).

### 4-1. 억제 기전 후보

| 안 | 기전 | 상태 |
|---|---|---|
| **A (기본)** | **적대 학습 (GRL)** — 잠재 z 에 신원 헤드를 달고 기울기 반전으로 신원을 예측 불가능하게 민다. λ 로 강도 조절 | v1 PoC 존재 (`src/encoder/train_disentangled.py`) — **설계만 참고, 코드는 새로 작성.** ⚠️ 한쪽눈 64×64 예비라 수치 인용 금지 |
| B | **정보 병목 (VIB)** — z 에 잡음·KL 제약 | A 가 파레토를 못 만들면 |
| C | **사후 선형 투영 제거 (ISP)** | **대조군으로만.** 선형만 내려가고 MLP 는 그대로면 프로브 회피다. 최신 문헌도 "선형만 인증"이라고 자인한다 (`RELATED_WORK.md` §C) |

### 4-2. 평가 규칙 🔒

**공격자는 학습 적대자와 달라야 한다.** 억제 학습에 쓴 신원 헤드로 평가하면
자기 적대자의 약점을 재는 것이다.

평가는 반드시 **동결된 z 위에 새로 학습한 프로브**로 하고, **선형·MLP 를 둘 다** 낸다.
이 프로젝트에서 두 방식의 차이가 두 번 결정적이었다 (광학 0.077 vs 0.202,
ours 재식별 0.478 vs 0.635).

### 4-3. 스윕

λ ∈ {0, 0.05, 0.1, 0.3, 1.0, 3.0} × D ∈ {8, 16, 32}

- λ=0, D=16 이 기준선과 같아야 한다 — **연속성 검증**으로 쓴다.
- 비용: 전체 5fold×3seed 는 조합마다 4.4시간이라 불가능 → 탐색은 fold 0·1 × 3 seed,
  파레토에서 고른 후보 1~2개만 5fold×3seed 로 확정.
- **탐색 단계 숫자는 확정 값으로 인용하지 않는다.**

### 4-4. 게이트 (이전 G-P)

| | 기준 |
|---|---|
| G-P1 파레토 성립 | 깜빡임 검출 비열등(δ=0.02)을 유지하면서 재식별 < **0.086** (균등 chance 0.0175 의 5배)인 점이 1개 이상 |
| G-P2 기전 검증 | 억제 전/후 × 선형/MLP 4칸. **선형만 내려가고 MLP 가 그대로면 FAIL** |
| G-P3 복원 장벽 | §3-5 의 G-R2 를 억제 후에도 만족 |

**현재 위치**: 기준선 재식별 0.6345 → G-P1 까지 **7.4배** 남았다.
억제 기전 없이는 도달 불가능하다.

### 4-5. 순서

```
[완료] 기준선 깜빡임 검출 성능    ours 0.9886 ± 0.0038
[완료] 기준선 재식별              0.6345 ± 0.0288 (랜덤 인코더 0.6261 과 동급)
   ↓
[다음] 복원 장벽 — 기준선          §3. 억제 전 기준점이 없으면 개선을 말할 수 없다
   ↓
       억제 + λ·D 스윕 + 파레토    §4
   ↓
       파레토 후보를 5fold×3seed 로 재실행
```

## 5. 그 밖의 후속 연구

### 5-1. 눈 건강 지표

깜빡임 빈도 · 불완전 깜빡임 비율 · PERCLOS.

**현재 불가능한 이유** — mEBAL2 의 이벤트가 전부 19프레임 고정창이라 **지속시간 라벨이 없다.**
연속 영상 event recall 도 라벨 커버리지(약 12%) 문제로 측정할 수 없다.
미라벨을 음성으로 놓고 재면 모델이 아니라 **라벨링 밀도**를 재게 된다.

→ 지속시간 라벨과 밀도 높은 연속 라벨이 있는 데이터가 확보되면 재개.

### 5-2. 조건 라벨이 있는 데이터셋 구축

조도계 값 · 카메라 거리 · 고개 각도(yaw/pitch) · 눈 개폐도가 기록된 자체 수집.
이번 논문의 가장 큰 한계(`EXPERIMENT_PLAN.md` §4-3)를 직접 해소한다.

### 5-3. 크로스 데이터셋 일반화

mEBAL2 크롭 밝기 34.8~45.4 vs Eyeblink8 102.7 — 밝기 차이가 사라진 게 아니라 **유예**됐다
(입력 정규화 결정으로 우회). 크로스 데이터셋 전이를 하려면 다시 꺼내야 한다.

> 심사하는 과정에서 '이거 논문으로 다 이미 공개돼 있는데 뭐하러 이거를 특허 받냐'
> 이렇게 하면 안 되니까" — 전사문 16:56

**논문 공개가 특허 심사에서 선행 기술이 되어 특허 등록을 막을 수 있다.**
