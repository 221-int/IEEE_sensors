**본문이 놓쳤던 것 (이후 세션이 찾음 — 반드시 승계할 것)**

1. **학습용 랜드마크(제공 CSV)와 배포용 랜드마크(우리가 돌리는 mediapipe)가 다른 소프트웨어다.**
   train/serve 기하가 조용히 갈라질 수 있다. 전처리 조건 7이 크롭 *함수*만 통일하고
   크롭 *입력의 출처*는 통일하지 않았다.
2. **blink/unblink 창의 세션 내 시간 위치가 피험자별로 어긋나 있다.**
   \|편차\|>0.10 인 사용자 17명, 최악 User 46 = −0.495(양성이 전반부, 음성이 후반부).
   → 모델이 눈꺼풀이 아니라 "녹화 몇 분째인가"를 맞출 수 있다.
   **`t_rel` 단독 분류기 대조군이 필요하다.**
3. **fold를 무작위로 자르면 이벤트 수가 fold 간 최대 3.77배 벌어진다.**
   이벤트 수로 층화하면 1.008배. fold 리스트를 파일에 고정할 것.
4. **분당 깜빡임이 2회 미만인 사용자 4명** — 생리학적으로 불가능하므로 라벨이 부분적이다.
   커버리지 기반 지표에 넣지 말 것.
5. **`grab()` 스킵은 공짜가 아니다.** h264는 참조 프레임 때문에 건너뛸 프레임도 디코딩해야 한다.

"눈 크롭 → 인코더 → D차원 벡터 → 판정" 에서 D와 인코더를 원점에서 설계한다.
기본값을 쓰지 마라. mEBAL2 기준으로 근거를 대라.

네 축을 각각 검토해라. "가장 흔한 방식 유지"를 고르더라도 근거가 필요하다.

축 1 — 입력 표현
  후보: 단일 프레임 / 19프레임 시퀀스 통째 / 프레임 차분·시간 미분 / 조합
  생각할 것:
  - mEBAL2의 라벨 단위가 애초에 19프레임 이벤트다. 창 안의 개별 프레임에는 라벨이 없다.
    단일 프레임 표현을 고르면 프레임 라벨을 발명해야 한다. 그 근거가 있는가?
  - 외형은 정적이고 깜빡임은 동적이다. 이 성질을 입력 단계에서 쓸 수 있는가? 대가는?
  - 검출 결측 8.8% 구간에서는 인접 프레임이 연속이 아니다. 차분 계열은 여기서 어떻게 되나?

축 2 — 학습 목적함수
  후보: 복원(오토인코더) / 깜빡임 지도학습 직접 / 대조학습 / 시간적 예측 / 조합
  생각할 것:
  - 복원 목적은 "외형을 보존하라"는 지시다. 눈 크롭에서 외형은 곧 신원이다.
    이 가설이 맞는지 가장 싸게 검증할 실험은 무엇인가? 설계 결정보다 먼저 그걸 해라

축 3 — 병목의 형태
  후보: 연속 실수 D차원 / 변분 정보 병목 / 이산 코드(VQ 등) / 희소성 / 양자화 비트수
  생각할 것:
  - 58명을 식별하는 데 필요한 정보량은 log2(58) = 5.9 비트다
  - 연속 실수는 D=1이어도 이론상 무한 비트를 담는다. 그렇다면 "차원을 줄인다"와
    "표현 가능한 정보량을 제한한다"는 같은 축인가 다른 축인가? 이 구분을 명확히 답해라

축 4 — 신원 억제 기전
  후보: 적대 학습(GRL 등) / 상호정보 최소화 / 사후 투영 제거 / 없음
  생각할 것:
  - 학습 중에 억제하는 것과 학습 후에 제거하는 것의 차이는? 배포 비용은 어디에 붙나?
  - 선형 억제와 비선형 억제의 차이가 프로브 종류(선형/MLP)에 어떻게 드러나나?

필수 요구사항
  - 네 축은 서로 교락된다. 한 번에 여러 축을 바꾸면 무엇이 효과를 냈는지 모른다.
    한 번에 하나씩 바꾸는 ablation 순서를 명시해라
  - 각 설계안마다 실패 시나리오를 먼저 적어라. "이 안이 틀렸다면 어떤 숫자로 드러나는가"
  - 각 설계안의 Pi5 비용을 추정해라 (프레임당 ms, 예산 33.3 ms = 30 fps 대비).
    MMAC 계산과 근거를 같이 적어라

[먼저 잴 것] 설계안을 고르기 전에 반드시 나와야 하는 숫자들
════════════════════════════════════════════════════════════
전부 학습이 없거나 수 초짜리다. 이걸 재기 전에 설계를 확정하지 마라.
목적은 "재식별이 높게 나올 때 그게 무엇 때문인지" 미리 좌표축을 만드는 것이다.

  (a) 랜덤 초기화 인코더 프로브 — 학습하지 않은 인코더로 벡터를 뽑아 58-way 재식별
      → 높게 나오면 "목적함수가 원인"이라는 가설은 그 자리에서 죽는다.
        학습을 안 했는데 샌다면 원인은 입력(눈 크롭 자체가 신원 판별적)이다
  (b) 원본 픽셀 선형 프로브 — 재식별의 천장
  (c) 픽셀 PCA-32 프로브
  (d) (밝기, 선명도) 2차원 프로브 ★
      → 두 숫자만으로 58명을 맞힌다면, 재식별의 상당 부분은 신원이 아니라
        세션의 광학 서명이다. 이 대조군 없이는 세션 교락을 정량화할 방법이 없다
  (e) EAR 스칼라 프로브 — 최소 정보 기준선
  (f) 사용자 간 밝기·선명도 분산 (58명 × 20프레임 균등 샘플)
      → 밝기 정규화를 넣을지 여기서 결정한다. 지금은 정하지 마라

모든 프로브는 무작위 분할과 시간 블록 분할(세션 앞 70% 학습 / 뒤 30% 평가) 둘 다로 재라.
두 숫자의 격차가 "신원인가 세션인가"의 단서다. 단, 격차가 작게 나온다고 해서
"신원이다"의 증거가 되지는 않는다 — "이 분할 쌍으로는 둘을 못 가른다"는 뜻일 수도 있다.
그래서 (d)가 필요하다.

[이전 검토에서 나온 후보 — 검증하고 채택 여부를 네가 판단해라]
════════════════════════════════════════════════════════════
아래는 다른 세션에서 제안된 것이다. 정답으로 받지 말고 검증해라. 틀렸으면 틀렸다고 해라.

  ■ 이벤트당 단일 이산 코드로 정보량 상한을 강제한다
    이벤트마다 벡터가 아니라 K개 중 하나의 이산 코드를 내보내면
    I(신원;표현) ≤ log2(K) 가 구조적으로 강제된다는 주장.
    피험자 균형일 때 단일 이벤트 재식별 상한이 대략 K/58 이 된다는 계산이 붙어 있었다.
    (K=4 → 0.069, chance 0.017)

    검증할 것:
      - 이 상한이 어떤 가정 위에서 성립하는가. 가정이 깨지는 조건은?
      - 한 사람이 수백 개 이벤트를 만든다. 코드 분포 자체가 신원을 흘리지 않는가?
        (다중 이벤트 집계 공격을 반드시 별도로 재야 한다)
      - 프레임마다 코드를 주면 19×log2(K) 비트로 다시 열리지 않는가?
      - 배포가 양자화 전 연속 벡터를 내보내면 상한이 증발하지 않는가?
      - 1비트 과제(blink/unblink)에 K가 작아도 유용성이 유지되는가?
        유용성이 무너지면 상한은 무의미하다 — 정보 0인 상수 출력도 상한은 완벽하다

    이 안이 매력적인 이유는 성능 기대가 아니라 자기 검증성이다.
    재식별이 상한을 넘으면 그건 결과가 아니라 버그다. 이 성질을 가진 설계는 드물다.

  ■ 억제를 학습에 넣는 것보다 사후 투영 제거가 파레토 점당 비용이 훨씬 싸다
    (학습 중 억제는 λ마다 전체 재학습, 사후 제거는 행렬 하나)
    단 사후 선형 투영 제거는 선형 프로브에만 통하고 MLP 프로브에는 거의 안 통할 것이라는
    예측이 붙어 있었다. 이건 예측이지 측정이 아니다. 검증 항목으로 다뤄라.

[핵심 과제 2] 평가 설계 — 코드를 쓰기 전에 확정해야 한다
════════════════════════════════════════════════════════════
막혀 있는 결정이 있다. 이것부터 답해라.

  (A) 재식별 프로브를 폐쇄집합 58-way 분류로 갈 것인가, 검증(verification)으로 갈 것인가?
      - 폐쇄집합 58-way 분류기를 학습하려면 58명 전원이 train에 있어야 한다
        → 재식별 축은 피험자 공유 + 시간 분리
      - 깜빡임 분류(유용성 축)는 피험자 분리여야 한다
      - 이 둘을 섞으면 코드와 저장 스키마를 다시 짜게 된다
      - 한 사람 1세션이므로 "같은 사람" 쌍이 전부 "같은 세션" 쌍이라는 점을 고려해라

  (B) 표현의 입력 단위를 프레임으로 할 것인가 19프레임 시퀀스로 할 것인가?
      → 저장 스키마가 여기서 갈린다

각 결정에 대해 선택지·근거·되돌릴 때의 비용을 적어라.
되돌림 비용을 줄이는 저장 스키마가 있다면 그것도 제안해라 —
나중에 프로토콜을 바꾸려고 58명 전량을 재추출하는 일은 피하고 싶다.

보고할 지표
  - privacy: 58-way 재식별 (chance 0.017). 선형 프로브와 MLP 프로브 둘 다.
             무작위 분할과 시간 블록 분할 병기
  - privacy 보조: 다중 이벤트 집계 공격 (사용자당 표현 N개 → 재식별), N ∈ {1, 10, 100}
  - utility: 균형 1:1 blink/unblink 이벤트 분류, 19프레임 시퀀스 단위,
             피험자 분리 5-fold, accuracy · PR-AUC · precision · fold 부트스트랩 CI
  - 파레토 곡선: x=privacy, y=utility.
    "유용성을 유지하면서 신원만 내려가는 구간이 존재하는가" 가 이 연구의 성립 조건이다
  - 안경 착용/미착용 분리 보고

측정하지 않는 것: 연속 event recall, frame false-alarm, PERCLOS, 불완전 깜빡임 비율

[대조군 — 빠뜨리면 결과가 무의미하다]
════════════════════════════════════════════════════════════
  1. EAR 스칼라 × 19프레임 시간창 → 우리와 동일한 판정 헤드 ★
     이걸 못 이기면 기여는 "표현"이 아니라 "학습된 판정 규칙"이다.
     가장 아프고 가장 필요한 대조군이다.
     EAR은 mEBAL2 제공 랜드마크로 계산해라. 같은 검출기·같은 얼굴 선택 규칙을 써야
     "다른 검출기라서 졌다"는 반론이 봉쇄된다
  2. 크롭 → 소형 CNN 직접 (표현 단계 없음) — 표현 단계의 기여
  3. 동일 차원 random projection — 학습의 기여
  4. 평균 벡터 (정보 0의 하한)
  5. 위 [먼저 잴 것] 의 (a)~(e) 전부

  ★ 안경 편향 주의. mEBAL2 안경 착용자는 깜빡임 시 EAR 하강폭이 얕다(User 1: 0.34→0.21).
    랜드마크가 렌즈 때문에 눈꺼풀을 못 따라가는 것으로 보인다.
    우리 방법은 크롭을 직접 보므로 덜 망가지고 EAR은 더 망가진다.
    즉 편향 방향이 우리에게 유리하다. "우리가 EAR을 이겼다"가 나와도
    방법이 좋아서가 아니라 베이스라인이 불리해서일 수 있다.
    전체에서 이기고 미착용군에서 지면 그건 베이스라인이 불리했던 것이다

[코드 규율 — 새로 짜므로 처음부터 넣어라]
════════════════════════════════════════════════════════════
아래는 이전 라운드에서 실제로 사고가 났던 항목이다. 새 코드는 처음부터 막고 시작한다.

  1. 임계값 격자를 공유 모듈 하나에 두고 모든 실험이 그것만 쓰게 해라.
     ours와 baseline에 다른 격자를 쓰면 결과가 뒤집힌다. 이 버그가 세 번 났다.
     성긴 고정 격자는 낮은 false-alarm 구간을 통째로 놓친다.
     분위수 기반 격자를 권장한다. 실험 스크립트마다 linspace 를 따로 쓰지 마라
  2. 시드 고정을 공유 모듈 하나로 만들어라.
     numpy, torch, cuda, random, PYTHONHASHSEED 전부 + cudnn.deterministic=True,
     cudnn.benchmark=False.
     이게 없으면 같은 시드에서 같은 숫자가 안 나오고, 보고하는 ± 가
     시드 분산이 아니라 시드 분산 + 비결정성이 된다
  3. 단일 시드 결과로 baseline과 비교하지 마라. 최소 3시드
  4. val에서 고르고 val에서 보고하지 마라. train/val/test를 분리하고
     임계값·에폭은 val에서 골라 얼려서 test에 적용해라. baseline도 완전히 동일한 절차로
  5. 임계값 보정을 쓸 거면 인과적이어야 한다(과거 프레임만 사용).
     녹화 전체의 분포를 미리 보는 보정은 실시간 배포가 불가능하다.
     성능이 좋아 보여도 해법으로 쓰지 마라
  6. 새 실험은 대조군을 먼저 정해라. 단일 지표는 거의 항상 오해를 만든다
     (예: PSNR만 보면 정보 0인 평균 이미지도 높게 나온다)
  7. 결과가 유리하게 나오면 베이스라인이 불리해진 것은 아닌지 먼저 의심해라
  8. 실행은 리포지토리 루트에서 python -m src.v2.<모듈>
