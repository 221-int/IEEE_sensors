## [신규] 슬라이드 A — 평가 프로토콜을 정식화했습니다

### 문제

지금까지 **에폭·임계값을 val 2명에서 고르고 그 val 2명에서 보고**했습니다.
시험 문제를 보고 공부한 뒤 그 시험을 치는 것과 같습니다.

### 프로토콜

피험자 단위 **4-fold 회전**. 각 fold에서

| | 역할 |
|---|---|
| train 4명 | 가중치 학습 |
| val 2명 | **에폭·임계값 선택** |
| test 2명 | **보고만.** 이 시점까지 한 번도 보지 않음 |

모든 피험자가 test 1회·val 1회 → **408 이벤트 전부가 test로 쓰임** (기존 74개 → 408개)
임계값은 val에서 고른 뒤 **얼려서** test에 적용. EAR도 **완전히 동일한 절차**.

### 결과 — val 선택 낙관이 실제로 얼마인지 측정됐습니다

| | val recall | **test recall** | 낙관 |
|---|---|---|---|
| 벡터 모델 | 0.938 | **0.854** | **+0.085** |

**이전에 보고했던 0.97은 과대평가였습니다.** 정직한 숫자는 0.854입니다.

| | test event recall | test false-alarm |
|---|---|---|
| **벡터 모델 (ours)** | **0.854 ± 0.226** | 0.0495 ± 0.1028 |
| **EAR (양눈 평균)** | **0.878 ± 0.206** | 0.0342 ± 0.0264 |

차이 −0.024, 흔들림 폭(±0.226) 안 → **여전히 우열 판정 불가.**
다만 이번에는 **프로토콜이 정당하므로 "대등"이라고 말할 수 있습니다.**

## [신규] 슬라이드 B — 새로 발견한 문제: 임계값이 사람을 넘어가지 못합니다 ★

*(이번 실험에서 새로 나온 것. 슬라이드 하나 값어치 있습니다)*

val에서 고른 임계값을 test 피험자에 적용했을 때 false-alarm이 얼마나 벗어나는가:

| | test FA 표준편차 | 예산(3%) 초과 | 최악 |
|---|---|---|---|
| 벡터 모델 | **0.1028** | 2 / 12 runs | **38.0%** |
| EAR | 0.0264 | 6 / 12 runs | 6.5% |

**우리 변동이 EAR의 3.9배입니다.** 성격도 다릅니다:

- **EAR** — 자주(6/12) 조금씩 빗나감. 최악 6.5%. **예측 가능한 실패**
- **우리** — 대체로 맞지만 간헐적으로 폭발(38%). **예측 불가능한 실패**

배포 시스템에서는 후자가 더 나쁩니다.

### 원인

EAR은 **눈 종횡비**라는 물리량이라 사람이 달라도 스케일이 비슷합니다.
우리 네트워크 출력 확률은 **신원별로 교정(calibration)되어 있지 않습니다.**

### 그래서 — 로드맵 ⑧ "초기 등록 구간"에 실측 근거가 생겼습니다

지금까지 근거 없이 로드맵에 있던 항목인데, **이 데이터가 그 필요성을 증명합니다.**
사용자별 초기 몇 초로 임계값을 교정하면 이 문제가 해결될 가능성이 큽니다.

### 덤으로: 두 방법의 실패 지점이 다릅니다

| fold | test 피험자 | 벡터 모델 | EAR |
|---|---|---|---|
| 0 | eb01+eb02 | 0.963 | 1.000 |
| 1 | eb03+eb04 | 0.903 | **0.521** ← EAR 붕괴 |
| 2 | eb08+eb09 | 0.981 | 1.000 |
| 3 | eb10+eb11 | **0.568** ← 우리 붕괴 | 0.991 |

**서로 다른 피험자에서 실패합니다.** 상보적일 가능성 → 앙상블 여지.

## [신규] 슬라이드 C — 신원 disentanglement PoC

> **표기 주의: 이 결과는 한쪽 눈(64×64) 파이프라인 기준의 예비 결과입니다.**
> 양눈(64×160) 전환 이전에 학습된 인코더이므로, 양눈 기준 재실행이 필요합니다.
> 슬라이드에 반드시 "(한쪽눈, 예비)"를 표기하세요. 안 붙이면 "지금 모델 얘기인가요?"에
> 답이 곤란해집니다.

gradient-reversal(DANN) + λ 워밍업. 8명, chance 재식별 = 0.125.

| λ | 깜빡임 AUC (유용성) | 재식별 (누출) |
|---|---|---|
| 0.0 | 0.984 | 0.942 |
| 0.05 | 0.987 | 0.945 |
| 0.1 | **0.988** | 0.913 |
| 0.2 | 0.983 | 0.868 |
| 0.5 | 0.975 | 0.819 |
| 1.0 | 0.978 | **0.767** |

**핵심: 재식별 0.942 → 0.767 로 떨어뜨리면서 깜빡임 AUC는 0.98대를 유지합니다.**
→ 신원은 유용성을 거의 잃지 않고 제거 가능하다는 기전이 확인됐습니다.

단, 아직 chance(0.125)까지는 멀고 8명뿐이라 **개념증명 수준**입니다.

### 왜 이게 중요해졌나 — 차원 스윕이 대안을 없앴습니다

| 잠재 차원 | 32 | 64 | 128 | 256 | 512 |
|---|---|---|---|---|---|
| 선형 프로브 재식별 | 0.995 | 0.998 | 0.999 | 0.999 | 0.999 |

**16배 좁혀도 누출이 0.45%p만 줄어듭니다.** 즉 **"벡터를 작게 만들면 프라이버시가 생긴다"는
직관은 틀렸습니다.** 명시적 disentanglement 외에 방법이 없다는 뜻입니다.

## [신규] 슬라이드 D — 복원 공격 ✅ 완료

### 질문

*"디코더를 배포하지 않으니 원본 복원 불가"* 라고 주장하는데,
**공격자가 디코더를 새로 학습하면?**

공격자는 벡터를 가지고 있고(그게 이 시스템이 내보내는 전부), 자기 이미지를 인코더에 넣어
**(이미지, 벡터) 쌍을 스스로 만들 수 있습니다.** 우리 디코더가 없다는 것은 장애물이지
불가능성이 아닙니다.

### 실험 설계

공격자가 train 피험자로 디코더를 처음부터 학습 → **학습에 없던 victim 신원**을 복원.

대조군이 핵심입니다. 눈 크롭은 저분산 그레이스케일이라 **정보 0으로도 PSNR이 높게 나옵니다.**

| | 뜻 |
|---|---|
| `ours` | 우리 디코더 — 상한 |
| `attacker` | 공격자가 새로 학습 — **실제 공격 성공도** |
| `mean` | 학습셋 평균 이미지 — **정보 0의 하한** |
| `shuffled` | 짝 안 맞는 벡터 — 디코더가 벡터를 읽는지 평균 얼굴을 외운 건지 판별 |

### 결과 (4개 victim 조합, PSNR dB)

| victim | ours | **attacker** | mean | shuffled |
|---|---|---|---|---|
| eb01+eb02 | 38.74 | 22.62 | 16.18 | 20.71 |
| eb03+eb04 | 34.71 | 26.38 | 20.34 | 21.43 |
| eb08+eb09 | 37.12 | 23.32 | 16.17 | 20.57 |
| eb10+eb11 | 24.58 | 20.22 | 16.36 | 17.38 |
| **평균** | **33.79** | **23.13** | **17.26** | **20.02** |

### 이득 분해 — 절반은 벡터와 무관합니다

```
공격자 총이득 +5.87 dB (평균이미지 대비)
  = 일반적인 눈 형태  +2.76 dB  (셔플 벡터로도 얻어짐, 47%)
  + 벡터 고유 정보    +3.11 dB  (53%)
```

**디코더 미배포로 얻는 장벽 = 10.65 dB** (우리 33.79 vs 공격자 23.13)

### 그림 (`docs/figures/recon_attack_*.png`)

원본 / 우리 디코더 / **공격자 디코더** / 평균이미지 / 셔플 5행 비교.
공격자 복원은 **어둡고 잡음이 심해 육안으로 사람을 식별할 수 없습니다.**
PSNR은 평균이미지보다 높은데 보기엔 더 나쁩니다 — PSNR만으로 판단하면 안 되는 예입니다.

### 결론 — 두 갈래로 나눠 말해야 합니다

**(1) 시각적 복원**: 부분적으로만 성공. 벡터가 외형 정보를 흘리는 건 맞지만(+3.11 dB),
육안 식별은 불가능한 수준입니다. "디코더 미배포"는 **10.65 dB의 실질적 장벽**입니다.
→ 이 부분은 우리 주장이 대체로 유지됩니다. 단 "복원 불가"가 아니라 **"복원 곤란"** 으로
표현을 낮춰야 합니다.

**(2) 신원 식별**: ★ **이쪽이 진짜 문제입니다.**
벡터에서 **선형 프로브만으로 재식별 99.8%** (chance 12.5%)입니다.
**이미지를 복원할 필요조차 없습니다.** 벡터를 그대로 분류기에 넣으면 사람이 특정됩니다.

> **프라이버시의 병목은 복원이 아니라 신원입니다.**
> 디코더를 감추는 것으로는 신원 누출을 전혀 막지 못합니다.
> → disentanglement가 유일한 해법이라는 결론이 여기서도 나옵니다.

## 예상 질문과 답

**Q. 정확도가 EAR보다 못한 거 아닌가요?**
평균은 −0.024 차이로 흔들림 폭(±0.226) 안입니다. 8명·408이벤트로는 우열이 판정되지 않습니다.
다만 **실패 패턴이 다릅니다** — EAR은 eb03/eb04에서, 우리는 eb10/eb11에서 무너집니다.

**Q. 그럼 벡터를 왜 씁니까?**
정확도가 아니라 **신원 제어 가능성** 때문입니다. EAR은 고정된 1차원 값이라 신원을 제어할
수단이 없습니다. 차원 스윕에서 확인된 것처럼 벡터를 좁히는 것으로도 안 되고,
**학습으로 축을 분리하는 것만 가능합니다**(슬라이드 C).

**Q. 8명으로 뭘 알 수 있습니까?**
설계 판단은 됩니다 — "128이 병목이 아니다", "차원 축소로는 프라이버시가 안 된다",
"임계값이 사람을 넘어가지 못한다" 세 가지가 이 데이터에서 나왔습니다.
**주장은 mEBAL2 이후에 합니다.**

**Q. 엣지 숫자는 믿을 만한가요?**
클립 1개(640×480) 기준입니다. 5분 연속·408 이벤트·스로틀 없음까지는 확인했으나,
해상도·피험자가 바뀌면 검출 단계가 달라집니다. 다중 클립 확장은 남아 있습니다.

**Q. "디코더를 배포 안 하니 안전하다"는 주장은 유지됩니까?**
표현을 낮춰야 합니다. 공격자가 디코더를 새로 학습하면 **부분 복원이 됩니다**
(평균이미지 대비 +5.87 dB, 그중 벡터 고유 기여 +3.11 dB). 다만 육안 식별은 불가능한
수준이고, 디코더 미배포는 **10.65 dB의 실질적 장벽**입니다.
→ "복원 불가"가 아니라 **"복원 곤란"**.
그리고 **더 중요한 건 복원이 아니라 신원입니다** — 재식별은 이미지를 복원하지 않고도
선형 프로브만으로 99.8%입니다.

**Q. 그래서 프라이버시는 어떻게 확보합니까?**
구조(디코더 미배포)만으로는 **신원 누출을 전혀 막지 못합니다.** 오늘 세 실험이
모두 같은 결론을 가리킵니다:
① 차원을 16배 좁혀도 재식별 99%+, ② 복원 공격은 부분 성공, ③ 재식별은 99.8%.
→ **표현 자체에서 신원을 제거하는 것(disentanglement) 외에 방법이 없습니다.**
