## [2026-08-05] 🔴 연구 범위를 눈 깜빡임 검출 + 에지 성능으로 축소

### 변경 날짜

**2026-08-05** (연구 미팅 당일). 근거는 같은 날 전사문.

### 변경 이유

1. **눈 깜빡임과 신원 사이의 논리적 연결이 약하다.**
   > "얼굴이 찍히는 불쾌감 제외하고서는 딱히 눈 깜빡임과 신원과의 연관성은 없어 보인단 말이야." (07:40)

   본인도 같은 인식이었다. > "눈 깜빡임이랑 의미가 약간 좀 연결이 잘 안 되는 느낌" (08:19)

2. **두 주제를 합치면 검증할 것이 너무 많다.**
   > "두 개가 너무 한 번에 어떻게 잘 묶여질지를 잘 모르겠어요. 검증해서 뭔가 보여줘야 하는 게 너무 많을 것 같은데" (05:12)

   실제로 PROTOCOL §14·§15 는 게이트 5개(G-R1·G-R2·G-P1·G-P2·G-P3)를 추가로 요구했고
   두 페이즈 모두 **스크립트조차 없는 상태**였다. 재식별 0.6345 → 게이트 0.086 까지 7.4배 격차.

3. **IEEE Sensors Letters 4페이지에 들어가지 않는다.**
   > "인트로부터 릴레이티드 워크 쓰면 한 페이지는 넘어가고, 메소드도 그림을 넣어야 되고,
   > Overall Architecture 넣고 (…) 실험 결과 그래프 몇 개 넣으면 진짜 공간이 없어요." (09:07)

4. **신원 억제를 밀어붙인 실제 동기는 논문이 아니라 특허였다.**
   > "특허를 작성하려면 어느 정도 차별화된 알고리즘이 있어야 할 것 같아서 거기에다
   > 억지로 그냥 신원을 쑤셔 넣으려 했던 거거든요." (12:50)

   → 동기가 특허라면 특허에 넣는다. 논문에 넣을 이유가 아니다.

### 이전 목표 (2026-08-04 판, `docs/v2/PROTOCOL.md` §0)

- **최종 목표**: encoder 단에서 신원 재식별을 **불가능**하게 만드는 것 = 프라이버시 확보
- 프라이버시의 주 근거: **복원 장벽** (§14) / 보조 지표: 재식별 (§11 Phase 5)
- 눈 깜빡임 검출(유용성)은 **주장이 아니라 전제 조건** — EAR 비열등(δ=0.02)만 통과하면 됨
- 이번 라운드에 **억제 기전 + 복원 장벽 + 파레토를 포함**
- encoder 의 D·목적함수 확정은 파레토 이후 (**맨 뒤**)
- 제안 제목: *On-Device Identity-Disentangled Representation Learning for Eye Health Monitoring*

### 변경된 목표

- **최종 목표**: 원본 눈 이미지를 판정 단계에서 쓰지 않고, encoder 가 만든
  **embedding vector 만으로 eye blink detection** 을 수행하는 **경량 모델**을 만들고,
  그것이 **Raspberry Pi 5 같은 edge device 에서 실시간으로 동작**함을 보인다.
- 눈 깜빡임 검출은 전제 조건이 아니라 **주 기여**로 승격.
- 비교 대상: **EAR 기반 방법 + 원본 이미지 기반 분류 모델** (전사문 03:02, 04:04).
- 평가 축: 정확도 + **지연 시간 · FPS · 파라미터 수 · 모델 크기 · 메모리 · CPU** (03:11).
- 조건별 강건성 실험을 논문의 두 번째 축으로 (06:27, 10:29).
- 결론 문장: **"벡터 뽑아서 경량화해 라즈베리파이에서 잘 돌아간다"** (08:56).

## [2026-08-04] 신원 억제·복원 장벽·파레토를 이번 라운드에 포함

> ⚠️ **2026-08-05 에 철회됨.** 아래는 기록이다.

- 최종 목표를 "encoder 단 재식별 불가능 = 프라이버시 확보" 로 재확인.
- 복원 장벽(§14)이 프라이버시의 **주 근거**인데 v2 에서 한 번도 측정되지 않았음이 발견돼
  Phase 5-bis 로 필수화.
- encoder 확정표에서 **D 와 목적함수를 🔓 해제** — 유용성만 보고 확정하면 억제를 붙일 때
  재학습해야 하기 때문.
- 억제(GRL λ) × D 파레토를 Phase 7 로 신설.

## [2026-08-01] 프라이버시 주 근거를 복원 장벽으로, EAR 을 유용성 베이스라인으로

- 프라이버시의 근거는 복원 장벽이고 재식별은 그것을 엄격히 검증하는 **보조 지표**로 위계 정리.
- EAR 은 프라이버시 경쟁자가 아니라 **대체 대상 = 유용성 베이스라인**.
- 판정 기준을 우월이 아니라 **비열등(δ=0.02, 주 지표 PR-AUC)** 으로 고정. 🔒 재협상 없음.
- 데이터셋을 **mEBAL2 58명 단독**으로. Eyeblink8 은 v2 학습·평가에서 제외.
- 눈 건강 지표(PERCLOS·불완전 깜빡임)는 지속시간 라벨 부재로 **제외**.

## [2026-07-30] v1 주장 3건 철회

- "EAR 과 대등 / 우열 판정 불가" → **철회.** 임계값 격자 오류. 조밀 격자로 재면 EAR 에 진다.
- "디코더 미배포 → 원본 복원 **불가**" → **"복원 곤란"으로 하향.** 공격자가 디코더를 새로
  학습하면 미지 신원을 PSNR 23.13 dB 로 부분 복원.
- "차원 축소 = 프라이버시" → **기각.** 512→32 로 16배 좁혀도 선형 재식별 0.9992→0.9947.

## [2026-07-2x] 원본 픽셀 · EAR 규칙 기반 → 벡터 encoder + 학습 판정 모델

- 평가 두 축을 유용성 / 정보보호로 설정. **이때 프라이버시가 도입됐다.**
