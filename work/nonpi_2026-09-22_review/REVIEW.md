# ① 결과 검토 및 ② 전처리·배포 정합성 검토

2026-09-22. 원고·표·PDF, 기존 결과 JSON/NPZ와 체크포인트는 변경하지 않았다. 이번 작업은 완료된 수정 학습의 해석과 실행 코드 정합성을 다룬다. 새 모델 선택·새 학습·Pi 측정은 하지 않았다.

## 1. 수정된 결과를 사용할 수 있는가

`result_review.json`과 `review_results.py`가 근거다. 네 후보 각각 15회, 총 60회에 대해 저장 파일 SHA-256, 피험자·라벨·fold/seed 순서, AP 및 TP/FP/FN/TN을 대조했다. 모두 통과했다. CNN과 함께 저장된 EAR 대조군의 점수도 대조했다. 60개 CNN 모두 80 epoch 예산에 도달하기 전에 validation early stopping으로 종료했다. 마지막 종료 epoch의 최댓값은 vpres 31, Image-CNN 30, vdrop 27, GAP 42다. 이것은 학습 실패나 예산 초과가 없다는 확인이며 전역 최적점 수렴의 증명은 아니다.

| 모델 | 15회 평균 AP | run 간 SD | 파라미터, head 포함 | MMAC, 매 프레임 head 포함 |
|---|---:|---:|---:|---:|
| Ours(vpres) | 0.988227 | 0.005699 | 84,049 | 12.489536 |
| Image-CNN+TCN | 0.990494 | 0.004194 | 476,161 | 31.852480 |
| vdrop | 0.986351 | 0.006969 | 55,377 | 3.490624 |
| GAP+TCN | 0.982621 | 0.015122 | 37,889 | 31.414208 |

원자료: `../nonpi_2026-09-21_maskfix/results/comparison.json`, 각 `train_*.json`, `records/`. SD를 평균의 신뢰구간으로 표시하면 안 된다. 동일 피험자가 seed마다 반복되고 학습 집합도 겹친다.

GAP의 낮은 평균은 특히 fold 1에 집중된다(fold 평균 0.955297, 최저 fold1/seed0 0.946680). 해당 런의 best epoch는 27, 종료는 37로 정상적인 사전 고정 규칙을 따른다. 낮은 런만 제외하거나 재시도하여 좋은 seed로 교체하지 않는다. GAP은 U53 AP 0.826055, U54 0.935258의 약점이 있는 반면 U1에서는 0.985139로 좋다. 한 아키텍처가 모든 사용자에 우세하지 않는다.

## 2. 통계 해석: 세 추정량을 섞지 않기

Ours minus Image-CNN의 차이는 다음과 같다. 모두 57명 subject cluster, 2,000 bootstrap draws, 고정된 학습 모델에 조건부인 구간이다.

| 추정량 | 차이 | 95% CI | 해석 |
|---|---:|---|---|
| 15회 AP 차이의 평균 | −0.002267 | [−0.004492, −0.000224] | 위 평균 표의 차이와 직접 대응 |
| 모든 run의 점수를 합친 pooled AP 차이 | −0.003547 | [−0.006487, −0.001382] | 기존 프로토콜의 pooled 비교 |
| 사람별 AP 차이의 동일 가중 평균 | −0.004473 | [−0.008379, −0.001726] | 이벤트가 많은 사람의 지배를 줄인 민감도 |

첫 행은 `run_mean_ci.json`과 `run_mean_ci.py`, 나머지는 `result_review.json` 및 기존 `comparison.json`이 출처다. run-mean의 bootstrap은 같은 피험자를 세 seed에서 함께 재표집하고 각 run의 AP를 다시 계산한다. fold 전체가 비는 표본은 정의 불가능하므로 NaN 처리한다. 이것은 새 학습을 반복한 불확실성까지 포함하지 않는다.

사전 사용한 δ=0.02에서 세 추정량 모두 비열등이며, 정확도 차이의 CI는 모두 음수다. 두 결론은 동시에 성립한다. δ=0.01에서도 모두 비열등이다. δ=0.005에서는 run-mean만 통과하고 pooled·subject-macro는 유보다. 결과에 유리한 추정량이나 마진으로 주분석을 교체하지 않는다. δ=0.02가 실제 사용에서 허용 가능한 손실이라는 근거는 통계 통과 자체로 생기지 않는다. 배포의 오경보·미검출 허용 기준과 별도로 설명해야 한다.

GAP 대비 pooled 차이 +0.005648의 CI는 [−0.000939, +0.014908]이다. 우월성 입증으로 쓰지 않는다. vdrop−vpres는 −0.001719 [−0.003904, +0.000176]이므로 세로 해상도 보존의 필수성을 입증하지 못한다. D=16과 vpres를 본 실험의 고정 설계로 유지하고 대조군의 장단점을 공개하는 것이 타당하다. 테스트와 외부 pilot을 이미 본 상태에서 승자를 골라 확증 검증으로 주장하지 않는다.

기존 Ours AP 0.988640에서 수정 후 0.988227로의 변화는 약 −0.000414다. 원 입력 수정 외에 NumPy 등 환경도 달라졌으므로 이 차이 전체를 결측 버그의 인과적 효과로 해석하지 않는다.

## 3. 사용자·실제 입력·외부 영상

`result_review.json`은 `../nonpi_2026-09-21_maskfix/post_train/`의 저장된 새 예측을 종합한다.

- U1: Ours AP 0.863010, Image-CNN 0.952204. 이전 Ours 0.820007보다 높지만 여전히 약하다. Ours seed별 FN은 19/28/10(각 양성 55개), FP는 8/1/18(각 음성 54개)이다. 안경·반사·어두운 영상은 관찰된 조건이지 단일 원인으로 확정된 것은 아니다.
- U54: Ours 0.993794, Image-CNN 0.996935. Ours의 전반적 실패자로 묶으면 부정확하다.
- 새로 함께 보고할 낮은 사용자: Ours U57 AP 0.949872(2,101개 이벤트), U42 0.953754(98개). 높은 전체 평균만으로 사용자 편차가 작다고 주장하지 않는다.
- 8명·160이벤트의 성능 독립 표본: 저장 랜드마크 크롭에서 Ours recall 평균 0.9875, 실제 FaceMesh 크롭에서 0.891667. Image-CNN은 0.9750→0.904167. 각 seed의 양성 분모는 80이며 서로 다른 240개 양성으로 취급하지 않는다. 검출 실패 4개 양성도 FN에 포함한다. 이 4건만으로 5%p 손실이 발생하므로 분류기 외의 입력 검출 실패가 실사용 성능에 중요하다. 전체 57명의 자연 분포나 외부 일반화 성능으로 확대 해석하지 않는다.
- 저장된 원 크롭 재추론과 test NPZ 사이, 진단 및 층화 표본 총 120개 모델·표본 조합의 임계값 판정 변화는 0건이다. 최대 logit 수치 차이 0.006604가 있어 bit-identical logits라고 쓰지는 않는다.

EyeBlink8 video9는 이미 관찰한 단일 영상, GT 41개 이벤트의 탐색적 평가다. 15회 source fit별 지표를 평균했으며 독립 외부 피험자 CI가 아니다. 아래 값은 현재 프레임 유효 + 19개 중 최소 14개 유효 정책, any-overlap 일대일 매칭이다.

| 모델 | event recall | event F1 | FP/min |
|---|---:|---:|---:|
| Ours | 0.993496 | 0.855425 | 5.640619 |
| Image-CNN | 0.996748 | 0.876904 | 4.998017 |
| vdrop | 0.998374 | 0.884739 | 4.069814 |
| GAP | 0.977236 | 0.930671 | 1.832606 |

경계 매칭을 IoU≥0.5로 강화하면 F1은 각각 0.675465/0.714794/0.628157/0.552783으로 낮아진다. 검출 후보의 존재와 정확한 폐안 구간 추정은 다른 과제다. Ours의 음성 프레임 양성률 0.006517은 Image-CNN 0.030442보다 낮지만 이벤트 FP/min은 더 높다. 짧은 양성 구간의 분절 및 매칭 단위가 영향을 줄 수 있으며, 이를 단일 모델 우열로 환원하지 않는다. 이 영상에서 후처리·임계값을 최적화하고 외부 검증이라고 부르지 않는다.

## 4. 크롭 불일치 원인과 수정

`crop_recheck.json`, `crop_runtime_numpy1.26.4.json`, `crop_runtime_numpy2.3.5.json`이 직접 증거다. 동일 원본 프레임·랜드마크와 OpenCV 4.11.0을 고정한 채 실행했다.

- U19 frame33969: 원 코드의 NumPy 1.26 경로에서 크롭 폭 243, NumPy 2.3 경로에서 244.
- U55 frame49892: 원 코드의 NumPy 1.26 경로에서 높이 144, NumPy 2.3 경로에서 143.
- float32 중심 좌표와 Python float 반폭을 더하고 뺄 때의 스칼라 승격 차이가 반 픽셀 경계 반올림을 바꾼다. float32 연산을 명시한 수정 코드는 두 환경 모두 저장 크롭과 완전히 일치한다.

`src/v2/dataset/crop.py`에서 이 정밀도를 명시했다. 원본 데이터와 저장 학습 크롭은 바꾸지 않았다. 따라서 완료된 수정 학습 60회는 이 수정 때문에 다시 학습할 필요가 없다. 8명 표본 전체를 원본 영상에서 다시 추출한 결과 **3,037/3,037 프레임이 저장 크롭과 비트 단위로 일치**했다(이전 3,035/3,037). `recrop_summary.json`이 근거다. 이 표본 밖 전 프레임의 보편적 bit equivalence를 주장하지 않는다.

동시에 실제 FaceMesh를 다시 실행한 새 크롭·마스크는 이 160이벤트 표본에서 이전 fresh 크롭·마스크와 모두 동일했다. 네 후보 × 8명 × 3 seed = 96개 조합을 수정된 모델로 재추론했으며 logit 변화와 판정 변화 모두 0이었다(`recrop_prediction_comparison.json`, `recrop_results/provider_stratified_sample.json`). 따라서 위 실제 입력 recall 수치는 재추출 후에도 유지된다. 이번 좌표 수정이 FaceMesh 자체의 검출 실패를 해결했다는 뜻은 아니다. EyeBlink8는 기존 저장 크롭에서 정책을 대조했으며, 새 crop 코드로 그 원본 전체를 재추출한 검증은 이번 범위에 포함하지 않는다.

## 5. 배포 규칙 반영

공통 구현은 `src/v2/deploy/inference_policy.py`이며 `run_video.py`, `run_video_power.py`, `pi_demo.py`가 사용한다.

1. 창은 시간 위치 19개, 최소 유효 크롭 14개, 현재 크롭도 유효해야 판정한다. 결측은 음성 확정이 아니라 판정 보류이며 평가에서 양성의 보류는 FN에 포함한다.
2. 얼굴 또는 크롭 실패도 링버퍼의 한 위치를 차지한다. 최신 프레임만 읽는 데모에서 sequence 번호가 건너뛰면 누락 위치를 채운다. 현재 데모는 실제 카메라 타임스탬프 기반 30 Hz 재표본화를 구현한 것이 아니므로 별도 시간 보정·지연 주장은 하지 않는다.
3. CNN 크롭 실패를 EAR 점수로 대신 판정하던 분기를 제거했다. 얼굴 부재·크롭 실패·불충분한 창에서 이전 CNN 확률을 재사용하지 않는다.
4. ONNX 모델 파일의 SHA-256과 함께 저장된 모델 계약에서 validation 임계값을 읽는다. logit과 sigmoid 확률의 대응, 창·정규화 조건을 검사한다. 계약이 없는 벤치마크는 가중치를 미검증/지연 전용으로 표시한다. 계약이 없는 CNN 데모는 명시적인 탐색용 `--blink-th` 없이는 시작하지 않는다. 기존 암묵적 0.5 기본값은 제거했다.
5. 데모 이벤트는 고정 임계값 이상의 연속 구간으로 통일했다. 기존 0.7 hysteresis와 wall-clock 0.03–1.2초 필터를 제거했다. 후보는 첫 양성에서 센다. 이것은 실제 눈감김 지속시간 측정이 아니다. 창 중심으로 붙인 offline 시각과 실제 출력 시각에는 9프레임 차이가 있으므로 둘을 혼동하지 않는다.
6. 실행 중 단축키로 깜빡임 임계값을 바꾸지 못하게 했다. 명시적인 CLI 변경은 탐색용 override로 로그에 구분한다.
7. 본래 `train_encoder.Bundle.batch`에도 완료된 수정 실험과 동일한 유효 행만 읽는 입력 수정을 반영했다. 결측 텐서는 encoder 이전에 0이다. 학습 데이터 제외 기준과 라벨을 변경하지 않았다.

학습의 이벤트 분류와 온라인 판정 가능 여부를 완전히 같은 것으로 취급하지 않는다. 학습은 e_valid의 최소 14개 조건을 유지하며 마지막 프레임이 결측인 이벤트도 포함할 수 있다. 온라인 추가 보류 규칙은 별도로 명시하고 평가에 적용했다(`provider_policy_review.json`, `test_policy.py`). 기존 pilot_min14 결과는 역사적 비교로 보존한다.

## 6. 검증·보존·다음 단계

테스트 14개와 세 실행 진입점의 CLI help 검사를 모두 통과했다(`verification.json`, `verification.log`). 실제 벤치마크 두 실행 루프·데모의 mock 카메라/ONNX 경로, 결측/프레임 누락/판정 복구, 모델 계약의 잘못된 가중치 거부, 학습 입력의 결측 참조 차단, 60개 외부 점수의 온라인/오프라인 후보 구간 일치, 기존 UI 검사를 포함한다. Pi 지연·전력 테스트는 아니다.

수정 전 해당 파일은 `before/`, 이번 변경만의 diff는 `changes.patch`에 보존한다. 기존 사용자 변경을 초기화하거나 git commit하지 않았다. 2026-09-21 실험은 당시 source hash를 고정했으므로 현재 소스에서 그 큐의 `prepare/run`을 다시 실행하면 보호 검사에 걸리는 것이 정상이다. 완료된 결과의 hash 검증은 여전히 통과한다. 과거 소스가 필요하면 `before/`를 참고하며 완료된 큐에 새 실험을 혼합하지 않는다.

남은 작업: 수정된 체크포인트의 새 ONNX·모델 계약 생성(③), 전체 외부 데이터 및 원시 연속영상의 더 넓은 검증, RNN 원자료 검증, Pi 재측정. 현재 계약 로더 테스트에는 기존 학습 그래프를 공학 검증 fixture로 사용했으며 그것을 수정된 60회 모델의 배포 결과로 바꾸어 부르지 않는다. 원고 수정은 계속 보류한다.

판단: 작은 정확도 손실과 계산량 절감이라는 기존 기여는 유지 가능하다. 다만 현재 가장 중요한 추가 검증은 더 높은 source AP를 찾는 작업보다 실제 검출 프론트엔드의 누락·크롭 변화와 연속영상 오경보를 정직하게 계량하는 것이다.
