# 투고 근거 보완 — 원고 수정 보류

> **중요한 후속 발견:** 아래 정합성 검사는 실제 참조 프레임과 저장된 점수의 재현을 확인한 것이며, 결측 대체 픽셀을 통한 학습 간섭까지 배제한 것은 아니다. 이후 `Bundle.batch`가 결측에 frame0(U1)을 대입하고 encoder BatchNorm이 마스크보다 먼저 작동하는 경로를 확인했다. Fold 0에서는 validation U1, fold 1에서는 test U1의 픽셀이 학습에 들어간다. 결측 픽셀만 바꿔 정상 프레임 임베딩·학습 기울기가 달라짐을 재현했다. 기존 학습 큐는 중단·보존했고, **4모델×15회의 수정된 재학습은 `../nonpi_2026-09-21_maskfix/`에서 진행한다.** 이하 예측 수치는 수정 전 checkpoint의 진단 결과이며 최종 투고 수치로 확정하지 않는다. 자세한 회귀 검증은 새 폴더 `preflight.py/json` 참조.

2026-09-21. 기존 `src/`, 기존 최종 결과와 원고는 수정하지 않았다. 새 분석·진단 코드와 산출물만 이 작업 폴더에 저장했다. 이 문서는 원고가 아니라 작업 기록이다.

### 8. 학습 결측 대체 픽셀 문제 — 수정 검증 완료, 최종 재학습 진행

`../nonpi_2026-09-21_maskfix/preflight.json`, `historical_code_trace.json`.

- 기존 `Bundle.batch`는 결측 프레임에 데이터의 frame0(U1)을 넣는다. CNN 인코더 BatchNorm이 시간 마스크보다 먼저 작동해, 결측 위치의 픽셀만 바꿔도 정상 위치 임베딩과 gradient가 달라졌다.
- Fold 0 train에서 결측 대체 283개/epoch가 validation 피험자 U1, fold 1 train에서 294개/epoch가 test 피험자 U1의 첫 프레임을 참조한다. **테스트 라벨이 전달됐다는 뜻은 아니지만, 피험자 분리와 맞지 않는 입력 내용의 간섭 경로다.**
- 기존 최종 JSON에 기록된 git commit의 trainer에도 같은 코드가 있다. 다만 당시 `git_dirty=true`라 실행된 모든 코드의 완전한 스냅샷이라고 단정하지 않는다.
- 수정은 실제 프레임만 읽고 결측 텐서를 encoder 전에 0으로 초기화하는 것이다. 27,758개 전체 이벤트에서 정상 위치 텐서·라벨·마스크가 그대로임을 확인했다. 결측 때문에 frame0에 접근하면 실패하도록 한 검사도 통과했다.
- 동일 초기 가중치·RNG의 회귀 실험에서 수정 전 vpres/vdrop은 결측 대체 내용에 따라 gradient가 변하고, 수정 후는 불변이다. Image-CNN은 인코더 BatchNorm이 없어 해당 실험에서 변화가 0이었다. 최종 성능 영향의 방향과 크기는 재학습 후에만 알 수 있다.
- 혼합을 피하기 위해 4개 모델 모두 15회씩 새로 학습한다. 기존 partial과 최종 모델은 보존한다. 현재 실행 위치는 `../nonpi_2026-09-21_maskfix/status.json`이다.

| 원고/표/PDF | 사용자 요청으로 보류 | 모든 실험 결과의 범위와 한계를 검토한 뒤 작성 |

공식 EyeBlink8 다운로드는 이번 시도에서 HTTP 401이었다(`external_download.json`). 웹 보안 우회나 제3자 연락은 하지 않았다. 공식 자료: https://www.blinkingmatters.com/research 및 https://www.blinkingmatters.com/files/upload/research/eyeblink8.zip . 로컬에는 9번 영상만 있어 전체 외부 검증 완료라고 표시하지 않는다.

`submission_audit/rnn_handoff_inventory.json`: Downloads의 표1 추가작업 ZIP과 전력측정 전달 ZIP에는 코드·Markdown만 있다. raw JSON/NPZ/PT/PTH는 없다. 요약 숫자를 독립적으로 검증한 숫자로 격상하지 않는다.

## 지금의 판단

기존 정확도·통계 수치의 정합성은 강화됐다. 동시에 입력 제공자·결측·운영 임계값·이벤트 경계 정의에 따라 실제 사용의 의미가 달라짐을 확인했다. 따라서 “실시간 깜빡임 검출 전체를 검증했다”는 넓은 주장은 아직 이르다. 진행 중인 대조군 결과, 더 넓은 외부 검증, 고정한 배포 규칙이 갖춰진 후 기여를 결정한다. 프라이버시·신원 제거·복원 방지 주장은 추가하지 않는다.
